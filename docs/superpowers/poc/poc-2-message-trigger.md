# PoC-2 Message 트리거 (실기기 절차)

> Message 자동화는 iOS 공식 문서상 "자동 실행 가능" 트리거 목록에 포함되어 있어 Notification보다 성공 가능성이 높다. 이 문서도 실기기에서만 실행 가능하며, 작성 시점에는 실행하지 않았다.

## 준비

1. iPhone에 `AssistantPoC`를 설치한다 (PoC-1과 동일 기기 사용 가능).
2. 단축어 앱 → 자동화 → 새 자동화 → **메시지** 선택.
   - 발신자: 테스트용 번호(가족·본인 세컨폰 등, 실제 타인 번호 사용 금지) 또는 "모든 메시지".
   - 문구 조건: 필요 시 특정 키워드로 제한.
3. "즉시 실행"과 **"잠금 시 실행 허용"**을 모두 켠다. 이 두 토글이 실제로 존재하는지, 켜지지 않는 경우가 있는지 기록한다.
4. 동작에 **"비서에 저장"**(`CaptureIntent`) 액션을 추가하고, 메시지 발신자·본문을 각각 `sender`/`text` 파라미터에 연결한다. `source`는 `"MESSAGES"`로 지정한다.

## 시나리오

| # | 상황 | 절차 | 기록할 것 | 기대 결과 |
|---|---|---|---|---|
| 1 | 잠금 해제 상태 수신 | 테스트 번호로 문자 발송 | 확인 없이 실행되는지, `text`/`sender` 값 | 확인 없이 큐에 적재 |
| 2 | 잠금 상태 수신 | 화면 잠근 뒤 문자 발송 | `poc.log`의 `locked=` 값, 큐 적재 여부 | `locked=true`로 정상 적재 |
| 3 | 재부팅 후 첫 잠금 해제 전 수신 | 기기 재부팅 → 잠금 해제하지 않은 채로 문자 발송 | 자동화가 실행되는지(첫 잠금 해제 전에는 일부 iOS 보호 클래스 파일에 접근 불가할 수 있음), 실행된다면 App Group 파일 접근 성공 여부 | 실행 안 되거나 App Group 접근 실패 시 "첫 해제 전 수신분은 유실" 로 기록 |
| 4 | OTP 문자 수신 | "[Web발신] 인증번호 123456" 형태의 테스트 문자 발송 | `poc.log`에 `discarded:otp`로 기록되는지 | `RuleFilter`가 OTP로 판정해 큐에 적재하지 않아야 함 (PoC-2가 아니라 규칙 필터 자체 검증이지만 같이 확인) |

## 판정 기준 (스펙 §14 PoC-2)

- **통과**: 잠금 상태에서 확인 없이 발신자·본문이 큐에 저장됨(`locked=true`로 정상 적재).
- **주의 필요**: 재부팅 후 첫 잠금 해제 전 수신분이 처리되지 않는 경우 → 처리 방식(유실 vs 지연 처리)을 스펙에 명시.
- **실패**: 잠금 상태에서 전혀 실행되지 않거나 발신자·본문이 전달되지 않는 경우 → Message 자동화 경로도 폐기하고 공유 확장 경로만 유지.
- 판정 결과는 `docs/superpowers/poc/results.md`(Task 13에서 생성)에 기록한다.
