# PoC-1 Notification 트리거 (실기기 절차)

> 시뮬레이터에는 실제 알림 배너·단축어 자동화가 없어 이 PoC는 **실기기에서만** 판정 가능하다. 아래는 사용자가 iPhone에서 직접 따라 할 절차다. 이 문서 작성 시점에는 실기기 실행을 하지 않았다.

## 준비

1. iPhone(iOS 26+, iPhone 15 Pro 이상)에 `AssistantPoC`를 Xcode → Run(케이블 연결)으로 설치한다. `poc/ios/project.yml`의 서명 팀(`6626BYCJG4`, Automatic)이 실기기에도 그대로 적용된다.
2. 설정 → 알림 → 카카오톡·Instagram → 미리보기를 "항상"으로 설정한다(잠금 상태에서도 본문이 보여야 시나리오 3을 시험할 수 있다).
3. 단축어 앱 → 자동화 탭 → 새 자동화 → **알림** 선택 → 앱: 카카오톡, 필터: 없음.
   - "즉시 실행" 토글이 나타나는지 여부를 기록한다 (스펙 §문서 조사 결과 Notification 트리거는 공식적으로 "자동 실행 가능" 목록에 없어 미확인 상태).
4. 동작에 **"비서에 저장"**(`CaptureIntent`) 액션을 추가한다.
5. 단축어 입력 변수(알림 텍스트에서 사용 가능한 마법 변수 목록)를 본문(`text`) 파라미터에 연결할 수 있는지 확인하고, 가능한 변수 목록을 스크린샷으로 남긴다.

## 시나리오

각 시나리오 실행 후 앱을 열어 큐 목록과 `poc.log`(ContentView 하단 섹션)를 확인해 기록한다.

| # | 상황 | 절차 | 기록할 것 | 기대 결과 |
|---|---|---|---|---|
| 1 | 잠금 해제, 카톡 알림톡 수신 | 카카오톡으로 알림톡 전송 → 수신 대기 | 확인 배너 표시 여부, `text`/`title`/`appName` 값 | 배너 없이 자동 실행되면 이상적. 배너가 뜨면 탭 1회로 실행되는지 |
| 2 | 잠금 상태 수신 | 화면 잠근 뒤 동일 알림 수신 | 자동화 실행 여부, `poc.log`의 `locked=` 값 | `locked=true`로 큐에 적재되면 통과 |
| 3 | 미리보기 "잠금 해제 시" 설정 후 잠금 상태 수신 | 설정 변경 후 2와 동일 | `text`가 비어 있는지("알림이 있습니다" 같은 자리표시자인지) | 본문이 비어 있으면 이 설정에서는 PoC-1 가치 없음으로 기록 |
| 4 | 5초 안에 알림 3건 연속(묶음) | 짧은 간격으로 3건 발송 | 3건 모두 큐에 도착했는지, 순서·중복 여부 | 3건 모두 개별 항목으로 적재 |
| 5 | Instagram DM 알림 | Instagram DM 수신 | `title`/`text` 형식(발신자명 포함 여부 등) | 앱마다 필드 구성이 다를 수 있음을 기록 |
| 6 | 필터 "주문" 설정 후 "주문" 없는 알림 수신 | 자동화 필터 조건 추가 | 트리거가 실행되지 않는지 | 필터링된 알림은 큐에 없어야 함 |
| 7 | (있다면) iOS 27 기기에서 1~2 반복 | 동일 절차 | OS 버전 간 차이 | 있으면 스펙 §14 각주에 기록 |

## 판정 기준 (스펙 §14 PoC-1)

- **통과**: 본문(`text`)이 실질적으로 전달되고, 최소 1개 이상 시나리오에서 확인 배너 없이(또는 탭 1회 이내로) 큐 적재가 확인됨.
- **부분 통과 / 대안 채택**: 본문은 전달되나 매번 확인 배너가 뜨는 경우 → 키워드 필터로 배너 노출 빈도를 줄이는 대안으로 전환.
- **실패**: 본문이 전달되지 않거나(`text`가 항상 비어 있음) 잠금 상태에서 전혀 실행되지 않는 경우 → Notification 경로는 폐기하고 공유 확장(Share Extension, PoC-8) 경로만 유지.
- 판정 결과와 시나리오별 원문 기록은 `docs/superpowers/poc/results.md`(Task 13에서 생성)에 옮겨 적는다.
