# PoC-7 한국어 하이브리드 검색 평가

판정 기준(스펙 §14): 샘플 500건(메일·알림톡·발화 혼합), 질문 50개(무근거 10개 포함) → **Top-5 ≥ 90%, 무근거 거절 ≥ 90%, 인용 검증 통과**.
스펙 §16에 따라 **합성 코퍼스만** 임베딩했다. 실제 사용자 items·Gmail 백필에는 `embed()`를 호출하지 않았고, worker `process` 경로에도 연결하지 않았다.

## 코퍼스·질문 (전부 합성)

- `poc/server/eval/corpus.jsonl` 500건 — 생성기 `eval/gen-corpus.ts`(시드 고정, 결정적). 주문 확인 메일 150(GMAIL), 알림톡 150(주문·배송·예약·청첩장·구독), 병원·택배 문자 80, 사용자 발화 70, 노이즈(뉴스레터·공지) 50. 문서 길이 최대 233자.
  - 정답이 되는 **앵커 50건은 직접 작성**(동일 상품·동일 몰의 날짜 변형 포함: 에어팟 본체/케이스/반품, 무신사 운동화 6월/8월, YES24 책 7월/8월, 넷플릭스 8월/9월 영수증, CGV 7월/9월, 서울치과 6월/9월 등). 나머지 450건은 앵커 주제와 겹치지 않는 풀에서 채웠다(잡담 채움 문장은 20종이 반복된다).
  - 무근거 질문 주제(보험·항공·PT·이사·여권·주식·전기요금·피아노 학원·와인·노트북 수리)는 코퍼스에 0건(grep 확인).
- `eval/questions.jsonl` 50문항 — 근거 있음 40(그중 날짜 필터 10), 무근거 10.

## 절차

```bash
cd poc/server
pgrep -x xcodebuild || echo ok            # 시뮬레이터 빌드와 동시 실행 금지(AGENTS.md §6)
# 워커 cron 정지 → 평가 → 정리 → cron 복구
deno run --allow-net --allow-env --allow-read --env-file=.env scripts/sql.ts \
  "select cron.alter_job((select jobid from cron.job where jobname = 'worker-every-minute'), active := false)"
deno run --allow-net --allow-env --allow-read --allow-write --env-file=.env eval/run-search-eval.ts --label small-512-kw1
EMBED_MODEL=text-embedding-3-large deno run ... eval/run-search-eval.ts --kw-weight 1 --label large-512-kw1   # 모델 대안
deno run ... eval/run-search-eval.ts --cleanup                                                                 # eval: 항목 삭제(청크 cascade)
deno run ... scripts/sql.ts "select cron.alter_job((select jobid from cron.job where jobname = 'worker-every-minute'), active := true)"
```

스크립트는 매 실행마다 `eval:` 항목을 지우고 다시 적재한다: `encrypt` → `insert_item(p_enqueue => false)`(process 잡·LLM 호출 없음) → `item_chunks` + `embed(..., "document")` 배치 64.
질문마다 (a) 키워드 전용 `hybrid_search(p_embedding => null)`, (b) 하이브리드 `embed([q], "query")` → `hybrid_search`의 Top-5를 잰다. 결과 원본은 `eval/out/<label>.json`(문항별 Top-5·유사도·(θ,τ) 스윕).

기준선 분석: 계획서 키워드 경로는 `plainto_tsquery('simple')`가 질문의 모든 어절(조사·어미 포함 "샀지", "언제")을 AND로 요구하고, 문서 전체와의 `similarity()`가 짧은 질의에서 0.2를 넘지 못해 거의 아무것도 찾지 못했다.
`0009_hybrid_search_kw.sql`: 질문 어절(질문어 제외)을 끝 1~2글자를 뗀 형태까지 부분 문자열로 맞추고 어절별 IDF 합으로 순위, RRF에 `p_kw_weight`. small 모델의 의미 검색은 짧은 한국어 질문을 말투가 비슷한 잡담 문서에 가깝게 둬서(정확 탐색으로도 같음, HNSW 문제 아님) 하이브리드가 키워드 전용보다 못한 경우가 있다.

하이브리드(large-512-kw1) 오답 2건: "강아지 예방접종 언제 가야 돼"(문서는 "초코(말티즈)… 종합백신 2차 접종일"), "9월에 배달 시킨 음식"(문서는 "배달의민족… 교촌치킨").

## 무근거 거절

검색 단계 신호로 거절을 시도했다. RRF 점수는 순위 기반이라 절대 신뢰도가 아니고(0008에서 임계 0.02는 근거 질문 38/40도 거절), 키워드 IDF 합 θ와 코사인 유사도 τ를 스윕했다.

| 실행 | 정답 질문 오거절 0 조건의 최대 거절 | 절충점(예) |
|---|---|---|
| small-512-kw1 | 0/10 | θ3·τ0.5 → 거절 6/10, 오거절 3/40 |
| large-512-kw1 | 0/10 | θ5·τ0.5 → 거절 7/10, 오거절 4/40 |

무근거 질문의 어절이 코퍼스의 다른 단어와 부분 일치하고("피아노 학원비" ↔ "영어 회화 학원", "여권 만료일" ↔ TVING "만료일", "자동차" → "자동" 우산), 의미 유사도도 근거 질문과 겹친다. **검색 단계 임계만으로는 무근거 거절 ≥ 90%를 달성할 수 없다.** 스펙 §9의 거절은 답변 모델이 검색 결과를 보고 "저장된 정보에서 확인되지 않음"을 내는 단계에서 일어나며, 0단계에는 답변 생성이 없다(계획서 Global Constraints). θ·τ는 이 50문항으로 고른 값이라 과적합 가능성이 있다.

## 비용 (OpenAI 임베딩, 토큰 기준)

- 실행 1회 = 문서 26,796 + 질문 815 = **27,611 토큰**(small·large 같은 토크나이저).
- 실행 수: small 5회, large 4회(1차 포함) + 테스트 소량 → small 약 13.8만 토큰(단가 $0.02/1M, 스펙 §3 → 약 $0.003), large 약 11만 토큰(단가 $0.13/1M 가정 → 약 $0.014). **합계 약 $0.02 미만.**

## 판정

**부분.** Top-5 ≥ 90%는 하이브리드 + `text-embedding-3-large`(512차원)에서만 충족(37~38/40). 스펙의 `text-embedding-3-small`은 31~33/40, 임베딩 보류 동안 쓰는 키워드 전용 경로는 32~34/40(80~85%). 무근거 거절은 검색 단계에서 최대 7/10(오거절 동반)이라 미충족. 인용 검증은 답변 생성이 필요해 0단계에서 측정하지 않았다.
따라서 스펙 §16의 "PoC-7 통과 시 실제 데이터 임베딩 활성화" 조건은 아직 충족되지 않았다(약관 사유 보류는 2026-09-26 해제).

다음 조치:
1. 임베딩 모델을 `text-embedding-3-large`(`dimensions: 512`, 스키마 그대로)로 바꾸는 스펙 결정(§2·§3·§16). 코드는 `EMBED_MODEL` 환경변수로 이미 전환된다.
2. 무근거 거절·인용 검증은 답변 단계(gpt-6-luna/sol, `store: false`)로 같은 50문항을 재는 평가 태스크를 추가한다(검색 결과 Top-5 + 문장별 `source_item_ids`).
3. 키워드 전용 경로 개선 후보: 오답 사례(동의어: 예방접종↔백신, 배달↔배달의민족 가게명) — 동의어 사전 또는 질의 확장.
