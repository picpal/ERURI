Architecture Report · 2026-09-23

iOS 개인 비서

메일·문자·앱 알림·공유 항목을 하나의 개인 컨텍스트로 모아 일정을 제안하고, 출처와 함께 답하는 앱. 스펙 v3(Codex 2차 리뷰 반영) 기준의 구조·흐름·기능 목록.

01 · System Architecture

시스템 아키텍처

iPhone은 iOS만 할 수 있는 일(수집·필터·EventKit·푸시 수신)을 맡고, 나머지 처리는 Supabase Edge Function이 담당한다. 두 액센트가 이 설계의 핵심 지점이다.

기기가 맡는 것

  • Shortcuts 트리거 → App Intent 수집 (문자는 무확인, 앱 알림은 배너 탭 예상)
  • 규칙 필터(OTP·카드·계좌·연락처) + Foundation Models 분류로 개인 대화 폐기
  • App Group SQLite 큐, background URLSession 전송
  • 알림 액션 → EventKit 쓰기, executions로 멱등 보장

서버가 맡는 것

  • Gmail Pub/Sub 수신, watch 갱신, historyId 복구
  • 봉투 암호화 저장, jobs 영속 큐로 분류·추출·임베딩
  • proposals 생성 후 APNs 발송
  • chat: tsvector+trgm ∪ pgvector RRF, 인용 서버 검증

확정 스택

  • SwiftUI · App Intents · EventKit · Foundation Models
  • Supabase Free (Postgres 17, pgvector, pg_cron, Edge Deno)
  • claude-haiku-4-5 추출 · claude-sonnet-5 채팅
  • Voyage voyage-4-lite 512차원 (약관 확인 후)

02 · Data Flow

수집 → 필터 → 저장 → 추출 → 제안 → 확인

역할별로 데이터가 어떤 형태로 손을 바꾸는지. 액센트는 이 제품의 핵심 순간인 "잠금화면에서 확인"으로 들어가는 제안 푸시다.

03 · Sequence

메일 수신 → 잠금화면에서 캘린더 추가

Gmail 푸시부터 EventKit 저장·보고까지. 캘린더 쓰기는 executions에 기록이 없을 때만 실행해 같은 알림을 두 번 눌러도 일정이 한 건만 생긴다.

04 · Flowchart

채팅 검색 · 답변 흐름

구조화 질문은 SQL을, 나머지는 하이브리드 검색을 탄다. 모델이 낸 인용은 서버가 검색 집합과 대조하고, 근거 없는 문장은 그대로 내보내지 않는다.

05 · Privacy Controls

개인정보 보호 계층

Superhuman·Spark 같은 서버 동기화형 구조를 그대로 두고, 여섯 층으로 보호한다. 액센트는 보호 범위를 정직하게 한정한 암호화 층이다. 실제 1차 방어는 접근 통제와 짧은 보관이다.
