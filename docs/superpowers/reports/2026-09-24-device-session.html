Summary

이 세션이 끝나면 PoC-1·2·3·5가 "통과/실패"로 확정되고, PoC-8 기기 부분과 PoC-9 가 실기기에서 재확인된다.

현재 판정표: PoC-1·2 미검증, PoC-3·5·8 부분, PoC-9 통과(시뮬레이터). 디버그 훅·시뮬레이터 대체는 "부분"이며 통과가 아니다(AGENTS §5-8).

세션 목표

  • ＋PoC-1·2 단축어 알림·메시지 트리거가 본문·앱명·발신자를 CaptureIntent에 넘기는지, 잠금 중 무확인 실행되는지
  • ＋PoC-3 실기기 FM 벤치마크 p95·개인 대화 통과율·알림톡 폐기율, 메모리, 백그라운드 rateLimited
  • ＋PoC-5 잠금 화면에서 .authenticationRequired 액션이 Face ID/암호 후 이벤트 1건만 쓰는지
  • ＋PoC-8·9 실기기 공유 시트 → 큐, 앱 종료·오프라인 후 업로드

확인 필요 — 문서 간 불일치

  • —자동화 개수: 계획서 "사용자 수동 단계"는 2개, PoC-1(카톡·인스타)+PoC-2(메시지) 절차와 results.md 대기 목록은 3개. 이 절차서는 3개로 진행.
  • —PoC-9 강제 종료: 스펙 §14는 "강제 종료 시 취소되는 것을 기록", 절차 문서는 "시뮬레이터 통과, 실기기는 회귀만". 시뮬레이터의 simctl terminate와 사용자의 앱 전환기 스와이프 종료는 같은 조건이 아닐 수 있다.
  • —INGEST_URL: 스킴 환경변수라 Xcode 에서 띄울 때만 적용. 홈 화면에서 다시 열면 기본값 http://localhost:8787(Uploader.swift:7).
  • —PoC-8 공유 시트: 절차 문서 사용자 단계 3은 "미검증으로 남긴 유일한 핵심 항목", 같은 문서 (d)는 XCUITest 통과. 판정표는 "부분" — 실기기 확인이 남은 것은 맞다.
  • —대기 목록 범위: results.md 실기기 대기 목록은 PoC-1·2·3·5 만. PoC-8·9 는 이 세션 지시로 추가.
  • —목 서버 명령: 지시문은 deno run -A, 절차 문서는 --allow-net --allow-env. 둘 다 동작하나 문서 기준(권한 최소)을 쓴다.

  • Mac 에 deno + 목 서버 poc/server/mock-ingest.ts, 방화벽에서 포트 허용
  • 카카오톡·Instagram 설치·로그인, 합성 문구를 보낼 두 번째 계정

02 · Mac Setup

Build & Install

서명·번들

  • 팀 6626BYCJG4, CODE_SIGN_STYLE: Automatic — 실기기에도 그대로 적용
  • 앱 com.picpal.assistant.poc, 공유 확장 com.picpal.assistant.poc.share
  • App Group group.com.picpal.assistant — 시뮬레이터는 프로비저닝을 강제하지 않았다. 실기기 설치 때 처음 검증된다

iPhone 쪽

  1. iPhone케이블 연결 → "이 컴퓨터 신뢰"
  2. iPhone설정 → 개인정보 보호 및 보안 → 개발자 모드 켜기 → 재시동
  3. iPhone첫 실행이 막히면 설정 → 일반 → VPN 및 기기 관리 → 개발자 앱 신뢰

Mac — UDID·빌드·설치

# 1. 기기 UDID
xcrun devicectl list devices

# 2. 프로젝트 생성 (poc/ios)
cd poc/ios && scripts/sim.sh gen

# 3-a. 권장: Xcode 에서 AssistantPoC 스킴 → 대상 기기 선택 → Run (⌘R)
#      스킴 편집 → Run → Arguments → Environment Variables 에 INGEST_URL (다음 슬라이드)

# 3-b. 명령줄 대안 (sim.sh 의 build 와 같은 형태, destination 만 실기기)
xcodebuild -project AssistantPoC.xcodeproj -scheme AssistantPoC \
  -destination 'platform=iOS,id=<UDID>' -derivedDataPath build \
  -allowProvisioningUpdates build
xcrun devicectl device install app --device <UDID> build/Build/Products/Debug-iphoneos/AssistantPoC.app
xcrun devicectl device process launch --device <UDID> com.picpal.assistant.poc

확인 필요 3-b 는 절차 문서에 없는 명령줄 경로다. 절차 문서가 지정한 방법은 Xcode Run. 3-b 로 띄우면 스킴의 INGEST_URL 이 적용되지 않는다.

02 · Mac Setup

Mock Server & LAN IP

PoC-8·9 에만 필요. 실기기에서 localhost 는 iPhone 자신이므로 Mac 의 LAN IP 를 넣는다.

# Mac LAN IP (Wi-Fi 가 en0 이 아니면 인터페이스를 바꾼다)
ipconfig getifaddr en0

# 목 서버 — 기본 포트 8787. 이 Mac 은 8787·8788 이 무관한 프로세스에 점유된 이력이 있다
lsof -nP -iTCP:8787 -sTCP:LISTEN
MOCK_INGEST_PORT=8799 deno run --allow-net --allow-env poc/server/mock-ingest.ts   # 점유 시

# 도착 확인 (Mac)
curl -s http://<MAC_IP>:<PORT>/received

엔드포인트

  • POST /ingest — JSON 항목 (202)
  • PUT /upload/<id> — 파일 바이트
  • GET /received — 도착 목록 (bytes, at)

앱에 IP 넣기

  1. MacXcode 스킴 편집 → Run → Environment Variables → INGEST_URL = http://<MAC_IP>:<PORT>
  2. Mac시스템 설정 → 네트워크 → 방화벽에서 deno 수신 허용
  3. iPhoneSafari 로 http://<MAC_IP>:<PORT>/received 를 열어 도달 확인

주의

확인 필요 INGEST_URL 은 Xcode 가 띄운 프로세스에만 들어간다. 홈 화면에서 앱을 다시 열면 http://localhost:8787 로 떨어진다. PoC-8·9 에서 앱을 "다시 여는" 단계는 Xcode ⌘R 로 재실행한다.

ATS

Info.plist 에 NSAllowsLocalNetworking = true. iOS 가 "로컬 네트워크" 권한을 물으면 허용한다 확인 필요 (절차 문서에 언급 없음).

PoC-1 · 현재 미검증 · Task 4

단축어 Notification 트리거 → CaptureIntent

iPhone only

준비

  1. iPhone설정 → 알림 → 카카오톡·Instagram → 미리보기 "항상"
  2. iPhone단축어 → 자동화 → 새 자동화 → 알림 → 앱: 카카오톡, 필터 없음. Instagram 도 하나 더
  3. iPhone"즉시 실행" 토글이 나타나는지 기록 (공식 "자동 실행 가능" 목록에 없음)
  4. iPhone동작 "비서에 저장" 추가 → 알림 마법 변수를 text·appName·title 에 연결, 변수 목록 스크린샷
  5. iPhone두 번째 계정에서 합성 문구만 발송 — 예: "[합성] 9월 25일 15시 예약 확정"

실행 단계

  1. 잠금 해제 상태에서 카톡 합성 알림톡 수신 (시나리오 1)
  2. 잠그고 15초 이상 기다린 뒤 수신 (2)
  3. 미리보기 "잠금 해제 시"로 바꾸고 2 반복 (3) → 끝나면 "항상" 복구
  4. 5초 안에 3건 연속 발송 (4)
  5. Instagram DM 수신 (5)
  6. 자동화 필터 "주문" 추가 후 "주문" 없는 알림 수신 (6)
  7. iOS 27 기기가 있으면 1~2 반복 (7)

매 시나리오 후 iPhone앱을 열어 큐 목록과 하단 poc.log 섹션을 본다.

관찰할 것 — poc.log 한 줄 = 인텐트 1회

CaptureIntent <결과> <ms>ms src=<출처> app=<appName|nil>
  titleLen=<n|-1> textLen=<n> sender=<nil|set> locked=<true|false>
  • textLen>0 본문 전달, app= 앱명 전달
  • 결과 queued:fm · queued:rules · discarded:otp|contact|fm:<kind>|fm-timeout|fm-unavailable|fm-error
  • 확인 배너 표시 여부, 잠금 시 locked=true
  • 에러면 CaptureIntent error <타입>

판정 기준 (스펙 §14)

  • 통과: 본문·앱명 전달 — textLen>0 이고 app= 로 앱 식별
  • 기록(설계 입력): 배너 여부, 잠금 동작, 미리보기 꺼짐, 묶음 알림
  • 대안: 본문 미전달 → 알림 경로 폐기·공유만. 배너 필수 → 키워드 필터로 탭 최소화
  • 연락처 폐기 규칙은 미배선 — 관찰 대상 아님

시나리오 표 — 원 절차 그대로

PoC-2 · 현재 미검증 · Task 4

단축어 Message 트리거 → CaptureIntent

iPhone only

준비

  1. iPhone단축어 → 자동화 → 새 자동화 → 메시지. 발신자: 테스트 번호 또는 "모든 메시지"

  4. iPhone시나리오 3 대비: 재부팅 전에 앱을 한 번 실행해 bfu.log(보호 등급 none)를 만들어 둔다

실행 단계

  1. 잠금 해제 상태에서 테스트 번호로 합성 문자 (시나리오 1)
  2. 잠그고 15초 이상 뒤 문자 (2) — 잠근 직후 약 10초는 isProtectedDataAvailable 이 true
  3. 합성 OTP "[Web발신] 인증번호 123456" (4)
  4. 세션 마지막에 재부팅 → 잠금 해제하지 않고 문자 → 해제 후 앱 bfu.log 섹션 확인 (3)

관찰할 것

  • 확인 없이 실행되는지, textLen·sender=set|nil (값은 안 남는다)
  • locked=true 로 큐 적재되는지
  • OTP → CaptureIntent discarded:otp
  • BFU: bfu.log 에 CaptureIntent start textLen=… locked=true 와 뒤이은 CaptureIntent error … 유무, poc.log 에는 없는지
  • 연락처 번호로 보내도 discarded:contact 는 안 나온다 (미배선)

판정 기준 (스펙 §14)

  • 통과: 잠금 상태에서 확인 없이 발신자·본문이 큐에 저장 (locked=true 적재)
  • 주의: BFU 수신분 미처리 → 유실 vs 지연 처리 방식을 스펙에 명시
  • 실패: 잠금 중 미실행 또는 발신자·본문 미전달 → Message 경로 폐기, 공유 확장만
  • BFU 해석: start 없음 = 자동화 미실행, start+error = 실행됐으나 큐(CUFUA) 접근 실패 → 유실

PoC-3 · 현재 부분 · Task 5

Foundation Models 한국어 분류 200건

⌘U on device

준비

  • iPhoneApple Intelligence 켜짐, 모델 다운로드 "완료"
  • MacXcode 대상 = 실기기, 스킴 AssistantPoC (테스트 타깃 AssistantCoreTests)
  • 시뮬레이터 결과는 참고용 — 호스트 Mac 이 appleIntelligenceNotEnabled 라 시뮬레이터 availability()=available 은 오표시였다
  • 픽스처: personal 100 (KakaoTalk 50·Instagram 29·iMessage 21), notice 100

실행 단계

  1. Mac⌘U 로 AssistantCoreTests/FMClassifierTests 실행 (Test navigator 에서 해당 클래스만)
  2. Mac실행 중 Debug navigator Memory 게이지 최대값 기록 (또는 Instruments Foundation Models 템플릿)
  3. MactestBenchmark 가 스킵되면 사유 기록: FM unavailable: … / 생성 실패: <코드>
  4. iPhone앱을 백그라운드로 두고 단축어 "비서에 저장"을 본문을 채워 10~20회 짧은 간격으로 실행

관찰할 것

FM_BENCH 로그와 App Group fm_bench.txt:

p95=<초>s personalPass=<n>/100 noticeDrop=<n>/100
errors=<n> timeouts=<n>
personalPassByApp=Instagram=a/29,KakaoTalk=b/50,iMessage=c/21
  • 행마다 새 세션, 에러·타임아웃은 폐기로 센다
  • 백그라운드: FM error rateLimited 빈도, queued:fm/queued:rules 비율, 지연 ms

판정 기준 (스펙 §14)

  • 통과: 세 수치 모두 — p95 < 3초, 개인 대화 통과율 ≤ 2% (personalPass ≤ 2/100), 알림톡 폐기율 ≤ 15% (noticeDrop ≤ 15/100)

  • 실패(하나라도 미달) → 규칙 필터만 + 카톡·인스타 경로 폐기

잠금 화면 알림 액션 → 백그라운드 EventKit

No APNs

준비

  • iPhone기기 암호(Face ID) 켜짐 확인
  • iPhone앱 → "권한 요청 (알림·캘린더)" → 두 대화상자 모두 허용
  • 알림은 앱이 예약하는 로컬 알림이라 APNs·PoC-4 가 필요 없다. 버튼이 쓰는 proposal id 는 p-local-1
  • 시뮬레이터에서 이미 통과: 백그라운드 쓰기, 재탭 dup skip, 콜드 스타트, 동시 탭. 남은 것은 잠금 화면 인증

실행 단계

  1. iPhone"10초 뒤 ADD_EVENT 로컬 알림" → 즉시 잠금
  2. iPhone잠금 화면 배너 길게 눌러 "캘린더에 추가" → Face ID/암호 요구 여부 기록 → 인증
  3. iPhone같은 버튼 다시 → 잠금 → 같은 액션 (두 번 탭)
  4. iPhone버튼 → 앱 전환기에서 위로 밀어 종료 → 잠금 → 액션 (콜드 스타트)
  5. iPhone캘린더 앱에서 이벤트 수, 앱 poc.log 확인

관찰할 것

  • 1회차: ADD ok p-local-1 … bg=true (시뮬레이터 로그에는 auth=3 도 남았다)
  • 재탭: 이벤트 증가 없음, ADD dup skip p-local-1 … unreported=1
  • 콜드 스타트: ADD ok … bg=true
  • 잠금 화면에서 앱이 열리지 않는지, 인증 요구가 뜨는지
  • 보고 실패 후 재탭: 서버가 없어 reported=0 그대로 — unreported=1 이 근거. 서버 보고(Task 9) 이후 재확인

판정 기준 (스펙 §14)

  • 통과: 잠금 상태 authenticationRequired 액션에서 앱을 열지 않고 캘린더에 1건만 생성 (두 번 탭·보고 실패 후 재탭 포함)
  • 실패 → 대안: foreground 액션으로 앱을 열어 실행

이 순서인 이유

  • 01권한 먼저: 알림·캘린더 대화상자를 한 번에 넘겨야 PoC-5 와 배너 관찰이 권한 문제로 섞이지 않는다.
  • 02자동화 다음: 합성 메시지를 보내는 두 번째 계정·번호가 준비된 초반에 몰아서 한다. 앱 목록 변수 스크린샷도 이때.
  • 03FM 은 케이블 연결 중: ⌘U·Memory 게이지가 Xcode 에 묶여 있다. 백그라운드 FM 10~20회는 단축어가 이미 만들어진 뒤라야 한다.
  • 04잠금 액션: APNs 불필요, 앱 버튼만으로 된다. 잠금·해제 반복이 많아 FM 측정과 섞지 않는다.
  • 05공유·종료 업로드: 목 서버·LAN IP 가 필요한 유일한 블록이라 뒤로 모은다.
  • 06재부팅은 맨 끝: 기기 재시동이 Xcode 연결·앱 상태를 끊는다. 재부팅 전 앱 1회 실행으로 bfu.log 준비.

실패 시 흔한 원인

  • —본문이 비어 온다 → 해당 앱 알림 미리보기 "항상"인지 확인 (PoC-1 준비 1).
  • —매번 확인 배너 → 자동화의 "즉시 실행"(실행 전 확인 끄기) 확인. 알림 트리거에 토글이 없으면 그 자체가 기록 대상.
  • —잠금인데 locked=false → 잠근 뒤 15초를 안 기다렸다.
  • —FM 벤치 스킵·modelNotReady → Apple Intelligence 모델 다운로드 "완료"까지 대기.
  • —Run 이 안 된다·기기 안 보임 → 개발자 모드 켜기 후 재시동, 개발자 앱 신뢰.
  • —업로드가 안 온다 → 앱을 홈 화면에서 다시 열어 INGEST_URL 이 빠졌는지, 방화벽, 같은 Wi-Fi.
  • —공유 확장·큐가 비어 있다 → App Group 프로비저닝 (실기기 첫 검증).
